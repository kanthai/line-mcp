Every install step was executed on a throwaway **privileged** Proxmox LXC (CT199, Debian 12
template, 2 cores / 4 GB) on the same host as CT103, then the CT was destroyed. This records
exactly what was run and what each step produced — including the LINE QR login and both read
paths (SQLite `direct` and PostgreSQL `postgres`).

## LINE install + QR login (step 3)

- **APK:** pulled the four splits from CT103's running install (`adb pull`) — `base.apk` +
  `split_config.arm64_v8a.apk` + two dpi splits — and `adb install-multiple -r` on CT199
  (**arm64-v8a**; Redroid `_64only` runs it through its native bridge `libnb.so`). "Success".
- **Screen access:** `tools/redroid-screen.py` (stdlib web viewer — no VNC/scrcpy on this image)
  on `:6080` streamed `adb screencap` and forwarded taps. Navigated
  Welcome → **Log in** → **Sub device** (not Main — Main logs your phone out) → **OK** →
  **Log in with QR code**. The QR screen rendered and regenerated on schedule.
- The QR was **not scanned** in this run (no spare LINE account; scanning with the account's
  phone would have signed CT103's sub-device out). So the login-gated checks below were
  exercised against a **read-only snapshot of CT103's real LINE DB** instead (a `sqlite3
  .backup` copy at `/srv/line-test-db`, destroyed with the CT) — 215 chats / 22 859 messages /
  4 220 contacts — which drives the exact same code paths a live login would.

## Bugs this run found and fixed (committed)

1. **`tools/line_sync_postgres.py` crashed on `chat_member`** — `ON CONFLICT (chat_id, mid)` with
   no matching unique index (the SQLite source declares no PK on chat/chat_member/groups/
   membership). Other tables silently never upserted. Fixed with a `CONFLICT_KEYS` map that both
   creates the unique index and drives the conflict target (matches CT101's mirror). Inherited
   from the line-assistant-agent copy; CT103 never hit it because its schema was created before
   this standalone script existed.
2. **`setup/04` didn't grant the `line` user direct-mode access** — added the docker
   `ExecStartPost=chmod o+x /var/lib/docker` drop-in, `line`→app-gid, and `chmod g+rx` on the
   app data dir (Android creates it `0700`; CT103 was `g+rx`'d by hand in 2026-05).
3. **`setup/05-verify.sh` parsed the MCP result wrong** — it was accepting an SSE
   `isError:true` payload as success; now parses the `data:` JSON.

## Caveat that remains (documented, not a bug)

Direct mode against the **live, actively-written** Redroid DB has WAL friction: LINE keeps
`naver_line`/`contact` in WAL mode with the `-shm` sidecar at `0600`, so an unprivileged
read-only open can fail (`attempt to write a readonly database` / can't open `-shm`). A static
snapshot (or a lower-traffic single-reader) is fine for direct mode; the **postgres mirror is
the robust path for the live multi-reader case, which is why CT103 runs `postgres` mode.**
